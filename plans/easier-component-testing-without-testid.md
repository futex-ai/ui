# Easier Component Testing Without Test Ids

## Status

In progress — Milestones 1–3 complete and verified (`npm run verify` green); Milestones 4–8 remaining.

## Goal

Make every interactive `@firna/ui` component easy to target in automated tests (Playwright on web, Appium/Detox/Maestro on native) using ONLY the accessibility tree: correct `accessibilityRole`s so `getByRole(role, { name })` resolves, overridable accessible names that default to the on-screen text, and explicit ARIA state attributes (`aria-selected` / `aria-pressed` / `aria-disabled`) so selected/pressed state is assertable. No interactive element should ship nameless. Explicitly NO `testID`, `nativeID`, `dataSet`, or `data-*` test handles are introduced anywhere — the library has zero today and keeps it that way.

## Principles

The testID-free toolbox — every change uses one of these five mechanisms, never a non-accessibility handle:

- **Correct role** — set `accessibilityRole` (`button` / `menuitem` / `option` / `radio` / `radiogroup` / `switch` / `dialog` / `menu`) so RNW emits the matching ARIA role and `getByRole(semanticRole, { name })` works.
- **Overridable accessible name (the escape hatch)** — a public `accessibilityLabel`-style prop that **defaults to the visible text**. Consumers get a stable, locale-controllable, duplicate-disambiguating name without diverging from on-screen copy by default (the `accessibilityLabel ?? visibleText` pattern already in `SegmentedControl` / `Input` / `Avatar`).
- **Explicit state attributes** — hard-code `aria-selected` / `aria-checked` / `aria-pressed` on selectable/toggle elements (RNW does NOT surface `accessibilityState.selected` on `role=button`), mirroring `Switch.tsx` / `RadioCard.tsx` / `SegmentedControl.tsx`, plus `aria-disabled` / `aria-expanded` where relevant, so `toBeChecked()` / `toHaveAttribute(...)` are assertable.
- **No nameless interactive elements** — icon-only buttons, unlabelled inputs, and roleless tap targets must require/derive a name or dev-warn when one cannot be computed.
- **Value-independent names for stateful triggers** — separate the stable handle (the field label) from the mutating selected value; move the value into `accessibilityValue` / `aria-valuetext` so a selector's name stays constant as the selection changes.

## Investigation Summary

- The library has **zero `testID` passthrough today**; the role+name happy path already works for several families (`Switch` `getByRole("switch", { name })`, `SegmentedControl` `getByRole("radio", { name })` with `toBeChecked()`, `Button` `getByRole("button", { name })`).
- **Content-derived names are fragile.** `DropdownList` rows (`src/dropdown/DropdownList.tsx:209-227`) and `RadioCard` (`src/radio/RadioCard.tsx:63`) have no explicit `accessibilityLabel`, so the computed name is the concatenation of title + secondary/body text (e.g. `"Cash basis Record income and expenses when money moves."`), forcing brittle partial-regex locators that collide on shared/substring titles.
- **Rows are `role=button`, not `menuitem`/`option`.** Every `DropdownList` interactive row is `accessibilityRole="button"` (`src/dropdown/DropdownList.tsx:211`), so action menus and selectors are not exposed as menus/listboxes.
- **`aria-selected` is dropped on web.** RNW does not surface `accessibilityState.selected` on `role=button`; dropdown rows, calendar day/year cells (`src/date/CalendarMonth.tsx:294-297, 253-258`), and wheel rows (`src/date/DateWheel.tsx:330-335`) currently only set `accessibilityState`, so selected state is not assertable and tests resort to `getComputedStyle(...).backgroundColor`.
- **Nameless icon-only controls exist.** The combobox chip-remove `Pressable` has a label but no `accessibilityRole="button"` (`src/dropdown/ComboboxMultiSelect.tsx:73-81`); the combobox search `TextInput` has no `accessibilityLabel` (`src/dropdown/ComboboxMultiSelect.tsx:84-92`); `Button` can ship icon-only with no name; `Switch` renders no text and is nameless without `accessibilityLabel`; `InputFrame` can leave a pressable suffix nameless.
- **Trigger names embed the value.** `selectorAccessibleLabel` (`src/dropdown/DropdownSelector.tsx:267-269`) produces `"Scheme, Standard"` and `DateTrigger` (`src/date/DateTrigger.tsx:134-141`) produces `"Year ends: 31 Mar 2026"`, so the handle mutates with every selection and tests must chase it.
- **Popover surfaces are roleless and nameless** (`src/dropdown/DropdownPortal.web.tsx:122`), reachable only by inner content text; the **modal backdrop shares the close button's name** and has no role (`src/modal/WebModalFrame.web.tsx:171`), causing strict-mode collisions.
- The repo already enforces source-assertion tests (`tests/unit/dropdownSource.test.ts`) that read component source and `assert.match` against the wiring — the chosen pattern for locking in these accessibility contracts.

## Scope Decisions

- **Default behaviour is preserved wherever cheap.** New props are optional; name-derivation defaults to visible text. Most existing `getByRole(..., { name })` specs keep passing; specs that target dropdown rows as `button` must migrate to `option`/`menuitem` (intended improvement, not silent breakage).
- **Two deliberately non-back-compat name changes**, each isolated to its own milestone with the affected specs migrated in lockstep: (a) the date wheel/native trigger name becomes value-independent (`"Year ends"` + `aria-valuetext`); (b) the modal backdrop name becomes `Dismiss {title}` (distinct from the close button). The dropdown **selector trigger** name change is handled conservatively via an opt-in `triggerLabel` prop (default keeps `"{label}, {value}"`), so existing selector specs stay green.
- **Dev-warnings, not throws.** Nameless-control guards are dev-only (gated so production output is byte-identical) and only `console.warn`. Use `process.env.NODE_ENV !== "production"` (statically replaced under Vite/Storybook, present under `node:test`); for files already in the RN runtime path, reuse a `__DEV__` guard with the `/* global __DEV__ */` comment.
- **Each milestone ships independently and keeps `npm run verify` green** (`format:check` → `test` → `typecheck` → `build` → `test:package` → `storybook:build` → `test:browser`). Per AGENTS.md, every component change ships a matching Storybook story update plus unit and/or browser tests in the same milestone.

## Non-Goals

- **NOT adding `testID`, `nativeID`, `dataSet`, or `data-*` passthrough** anywhere — not as test handles, not as a convenience prop. The only handles are role + accessible name + explicit ARIA state.
- **NOT migrating `davis` or any other downstream consumer.** This plan changes `@firna/ui` source, its stories, and its own test suite only.
- **Avatar is display-only and out of scope** beyond its existing `accessibilityLabel`; no interactive-targeting work is needed there.
- **NOT changing keyboard activation, focus management, hover bridging, or portal/dismiss mechanics** — role changes keep using the existing `onPress`/`keyProps` activation path.
