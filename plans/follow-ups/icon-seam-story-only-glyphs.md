# Icon seam holds glyphs that only stories draw

- **Severity:** Low. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-27, from the branch `calummoore/firna-rnw-seam-contract-mhsd`. The finding check of review round 1, finding 1, listed it outside the scope.
- **Location:** `src/primitives/icons.ts:4-9`, `src/primitives/icons.ts:12-106`, `src/primitives/icons.web.ts:9-103`, `tests/unit/primitives.test.ts:34-47`, `tests/unit/primitives.test.ts:217-229`, and the imports of the 15 glyphs in 16 story files: `src/stories/button.stories.tsx:2`, `src/stories/buttonExamples.tsx:4`, `src/stories/buttonLayoutExamples.tsx:4-14`, `src/stories/dateFieldExamples.tsx:2`, `src/stories/dropdownFieldExamples.tsx:5`, `src/stories/inputFieldExamples.tsx:2-10`, `src/stories/kanban.stories.tsx:2`, `src/stories/linkExamples.tsx:6`, `src/stories/listDenseRowsExample.tsx:6`, `src/stories/menuExamples.tsx:7-14`, `src/stories/menuSheetExamples.tsx:6`, `src/stories/segmentedExamples.tsx:2`, `src/stories/segmentedLabelExamples.tsx:2-8`, `src/stories/sharedExamples.tsx:1-9`, `src/stories/sortableList.stories.tsx:2`, and `src/stories/touchSurfaceExamples.tsx:6`.
- **Reason:** The icon seam, its header, and its glyph list came before the react-native-web route branch, which changed none of them.

- **Terms:**
  - **Icon seam:** the module pair through which Firna draws Lucide glyphs: `src/primitives/icons.ts` re-exports them from `lucide-react-native`, and `src/primitives/icons.web.ts` from `lucide-react`.
  - **Story:** a Storybook example under `src/stories/`, which only the web Storybook loads.
  - **Curated Lucide module:** a module that an app aliases in place of a Lucide package, and that exports only the glyphs that the app needs, to keep its bundle small.
  - **RNW route:** an app that draws its own screens with `react-native-web` (RNW) applies the rule of `@firna/ui/rnw`, and Firna then draws with RNW too.
- **Background:**
  - The header of `src/primitives/icons.ts`, at lines 4-9, says: "Every icon the library draws itself is imported through this module". It ends: "Add a glyph here only when a component needs it, and add it to the web module in the same change."
  - Both seam modules re-export the same 93 glyph names. The test "web and native primitive modules export the same names", at `tests/unit/primitives.test.ts:34-47`, keeps the two lists equal.
  - On 2026-11-27, a search of the imports from the icon seam in `src/` found 78 names that a component imports, and 15 names that only stories import: `Archive`, `Bell`, `ChevronUp`, `Columns2`, `DollarSign`, `Download`, `Mail`, `Mic`, `MoreHorizontal`, `Paperclip`, `Pin`, `Settings`, `ShieldQuestionMark`, `Table`, and `User`. Outside `src/stories/` and the two seam modules, a word search for these 15 names found only words in comments and the `Table` component.
  - The stories import their glyphs through the seam, because the test "no component imports react-native, react-native-svg, or lucide directly", at `tests/unit/primitives.test.ts:217-229`, rejects a Lucide import in each file under `src/` outside `src/primitives/`. That walk includes the stories.
  - Commit `c626a81`, pull request #166, added the icon seam, its header, the 15 story glyphs, and that test on 2026-09-16. So the header and the list have disagreed since that commit.
  - The package build leaves `src/stories/**` out, at `tsconfig.build.json:13`. The native Storybook loads its own stories from `storybook-native/stories`, at `storybook-native/.rnstorybook/main.ts:11`. So both built seam modules re-export the 15 names, and no package code uses them.
  - The published icon lists of the RNW route, `firnaIconNames` in `@firna/ui/rnw`, give the glyphs that each public subpath can draw. No list holds one of the 15 names.
  - An ES module bundler checks each re-exported name against the module that an app aliases. On 2026-11-27, esbuild bundled `@firna/ui/list` through the RNW rule, with `lucide-react-native` aliased to a curated module that exports only `ArrowUpRight`, the one glyph in the published list of `@firna/ui/list`. The build failed on 92 missing bindings. The first one was `Archive`, and all 15 story names were among them. Metro leaves a missing name `undefined`, so a Metro build does not fail.
  - The other 77 missing names are glyphs that other components draw. Only option D removes them too.
  - The review of the react-native-web route branch found the same build failure on 2026-11-27. Its finding check recommended the approach of option D, after the merge, as the fix that makes the published lists enough for such a build. The user, Cal, has not chosen that fix yet, and no follow-up item holds it yet.
- **Problem:** The header lets a glyph into the icon seam only when a component needs it, but 15 of the 93 glyphs serve only stories. The header and the list have disagreed since the seam came in.
- **Impact if no action:** Readers cannot tell which rule holds, so each new story glyph widens the gap. The package ships 15 re-exports that no package code uses, and an app that curates Lucide for an ES module bundler must provide them too.
- **Root question:** Which glyphs belong in the icon seam, so that its header and its list agree, and where do the stories get the other glyphs?
- **Options:**
  - **A.** Keep the 15 glyphs, and change the header so that it allows a glyph that a component or a story needs. The package keeps 15 re-exports that no package code uses. Effort: Small.
  - **B.** Give the stories their own icon module under `src/stories/`, which imports the 15 glyphs from `lucide-react`. Move the 16 story imports to it, and remove the 15 names from both seam modules. The test at `tests/unit/primitives.test.ts:217-229` must then allow that one module, which narrows a test of live code, so the user decides. Three of the 16 story files pass 300 lines: `src/stories/sharedExamples.tsx`, `src/stories/kanban.stories.tsx`, and `src/stories/sortableList.stories.tsx`. Effort: Small.
  - **C.** Change the stories to use glyphs that components already draw, and remove the 15 names from both seam modules. The examples lose glyphs that fit them, such as `Settings` and `Mail`. Each changed story needs new snapshot baselines, recorded on Linux as `AGENTS.md` says. C changes the same three long story files as B. Effort: Medium.
  - **D.** Give each glyph its own internal module pair, so that each module imports only the glyphs that it draws, and the seam has no shared list. A story then imports its own glyph modules, and no public subpath reaches them. Each glyph needs a native and a web module that the RNW rule routes, and the imports of 72 files change. Effort: Large.
- **Left out:**
  - Change nothing: the header and the code keep disagreeing, so it fails the goal.
  - Exclude all of `src/stories/` from the test, so that each story imports Lucide directly: it drops the rule for every story file, and B is better on every point, because B gives one place for the story glyphs.
- **Wider fix:** D. It removes the shared list, so no glyph that a subpath does not draw can bind in that subpath.
