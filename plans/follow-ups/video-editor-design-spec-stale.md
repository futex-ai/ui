# Video-editor design spec contradicts the code

- **Severity:** Low. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-04, from `conductor/agents-md-ui`, the investigation of the hand-written mockups.
- **Location:** `docs/superpowers/specs/2026-08-12-video-editor-ui-design.md`, lines 45, 49-50, 75-76, 102-103, and 110-119, `src/timeline/README.md:211`, `src/video-editor/README.md:191`, `src/timeline/timelineScrubValue.ts:54-59`, `src/timeline/timelineScrubValue.ts:61`, and `plans/video-editor-components.md:13`.
- **Reason:** The spec and the two READMEs that link it are outside the files of `conductor/agents-md-ui`, a change that edits only `AGENTS.md` and follow-up items.

- **Terms:**
  - **Video-editor spec:** `docs/superpowers/specs/2026-08-12-video-editor-ui-design.md`, the design spec of the `@firna/ui/timeline` and `@firna/ui/video-editor` families. It is the only file under `docs/superpowers/`.
  - **DOM backend:** the library's own web renderer, under `src/primitives/dom`. Since pull request #168, merged on 2026-09-17, it is the default web renderer in place of `react-native-web`. Since a user decision of 2026-11-26, an app that draws its own screens with `react-native-web` can draw the library with it too.
  - **Package smoke test:** `npm run test:package`. It packs the library and imports each entry point in a stub consumer that `scripts/package-smoke-stubs.mjs` writes.
- **Background:**
  - The spec starts with "Status: approved 2026-08-12". Pull request #153, commit `d998e0b`, added it with the two families on 2026-08-21.
  - `src/timeline/README.md:211` and `src/video-editor/README.md:191` link it as "Design spec".
  - Eight passages contradict the code:
    - Line 45 gives `TimelinePlayhead` a "Draggable head with a hairline through all tracks". The playhead takes no pointer events, at `src/timeline/TimelinePlayhead.tsx:1-7`. The ruler is the scrub surface, at `src/timeline/TimelineRuler.tsx:1-9` and `:183-186`. A drag on the ruler moves the playhead, so a user can still drag at the head.
    - Lines 49-50 put `applyTimelineEdits` in `timelineEditModel`. It lives in `src/timeline/timelineEditApply.ts:39`, as `src/timeline/README.md:191-193` says.
    - Lines 75-76 say that the arrow keys nudge a clip by a frame, and by a second with Shift. The code nudges only with `Alt` and an arrow key, at `src/timeline/timelineKeyboardModel.ts:55-56`, because bare arrows move the focus, as `src/timeline/README.md:152-157` says.
    - Lines 102-103 say that colours come from the theme and that "nothing is hardcoded". The letterbox, guides, safe area, and badge of the monitor use fixed colours on purpose, at `src/video-editor/videoEditorStyles.ts:42-88`. The comment at `:43-45` gives the reason.
    - Lines 110-112 sync the ruler, the lanes, and the gutter with "a scroll listener on web, an `Animated.ScrollView` on native". The ruler, the lanes, and the playhead share one horizontal `ScrollView` with no scroll-sync code, at `src/timeline/Timeline.tsx:11-13`.
    - Lines 113-115 say "react-native-web drops `accessibilityValue`", so they name `react-native-web` as the web renderer. By default, the DOM backend draws web, and it drops `accessibilityValue` on purpose, as `tests/unit/domProps.test.ts:99-116` pins. `react-native-web` draws the library only for an app that chooses it, and it drops `accessibilityValue` too. `plans/follow-ups/docs-name-react-native-web.md` calls such a behaviour of both renderers "web". `src/timeline/timelineScrubValue.ts:5-10` and `src/loader/README.md:100` still say "the web backend".
    - Lines 116-117 say that `role="slider"` and `role="gridcell"` are missing from the `Role` type of React Native. React Native 0.85.3 lists `slider`, at `node_modules/react-native/Libraries/Components/View/ViewAccessibility.d.ts:404`. It does not list `gridcell`. The doc comment of `sliderRoleProps` at `src/timeline/timelineScrubValue.ts:54-59` repeats the `slider` claim. The library's own `Role` type lists `slider` too, at `src/primitives/types/accessibility.ts:100`, but `sliderRoleProps` still casts the role, at `src/timeline/timelineScrubValue.ts:61`. So a fix of the comment also decides whether the cast stays.
    - Lines 118-119 say that new Lucide icons and new React Native APIs need stubs in `scripts/package-smoke-stubs.mjs`. Neither needs an edit there now:
      - The stub file imports its icon names from `scripts/package-smoke-icons.mjs`, at `:4`. That module reads the names from the built web icon seam, `dist/node/primitives/icons.web.js`, through `readWebLucideNames` in `scripts/rnw-icons.ts`.
      - A new Lucide icon goes into both `src/primitives/icons.ts` and `src/primitives/icons.web.ts`, as `src/primitives/icons.ts:9-11` says, and a unit test keeps the two lists the same.
      - The package smoke test no longer stubs React Native, as the comments at `scripts/package-smoke-stubs.mjs:6-13` and `:122-129` say. A new React Native name needs a type in `src/primitives/types` and an implementation in `src/primitives/dom`, as `src/primitives/README.md:268-269` says.
  - Two more lines belong to other follow-up items. Line 3 links the completed plan `plans/video-editor-components.md`. Line 44 names a clip selection ring that the code does not draw.
  - The rest of the spec repeats other sources. `src/timeline/README.md` covers the responsibilities, the time model, the edits, the interaction, the layout, and the pure helpers. `src/video-editor/README.md` covers the panels, their boundary, and their pure helpers. `AGENTS.md`, the shared skills, and the tests hold the house rules. For example, the file length at line 104 is a rule of the shared `typescript` skill: a target of 200 lines and a hard limit of 300. `AGENTS.md:59-60` says that no check enforces it yet. The stories show the Storybook demo.
  - Pull request #168 updated both READMEs and `docs/protocol/shared-ui-components.md` for the DOM backend, but not this spec.
- **Problem:** The spec contradicts the code in eight passages. The rest of it repeats content that the READMEs, the code comments, and the shared skills keep current.
