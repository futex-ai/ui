# Kanban component file passes the 300-line limit

- **Severity:** Low. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-02, from the branch `calummoore/dragselectableprovider-improvements`.
- **Location:** src/kanban/Kanban.tsx
- **Reason:** The file passed the limit before the drag-select branch, which added only two lines to it, so the split needs a branch of its own.

- **Terms:**
  - **Source-reading test:** a unit test that reads a source file as text and checks code patterns in it, such as the tests in tests/unit/kanban.test.ts.
- **Background:**
  - AGENTS.md says: "Keep files short - around 300 lines is an ideal length, split up the file if longer". No lint checks the length of a TypeScript file.
  - src/kanban/Kanban.tsx holds the `Kanban` board of `@firna/ui/kanban`. It has 312 lines in `@firna/ui` 4.0.0, and 314 lines after the drag-select branch added the drag-select ignore marker to the board root.
  - The file holds three responsibilities. The first is the public `KanbanProps<Card>` type with its doc comments, at lines 43 to 122. The second is the board model in the component: the grouping of cards into columns, the drag layout, and the lookup of the dragged card and its preview slot. The third is the render of the board, the columns, and the drag ghost.
  - Other parts of the board already have their own modules in src/kanban: `KanbanColumn.tsx`, `KanbanCard.tsx`, `KanbanChip.tsx`, `kanbanStyles.ts`, `kanbanDragModel.ts`, `kanbanDragDom.ts`, `useKanbanCardDrag.ts`, and `useKanbanCardDrag.web.ts`.
  - tests/unit/kanban.test.ts has 7 source-reading tests of Kanban.tsx. The test "kanban threads a per-column header accessory through to the column" checks that the `renderCard`, `renderColumnAccessory`, and `renderColumnEmpty` declarations of `KanbanProps` appear in Kanban.tsx in that order. The test "kanban groups a flat cards array into columns by accessor" checks the grouping code `map.get(cardColumnId(card, index))?.push(`.
  - tests/unit/testIDForwarding.test.ts and tests/unit/dragSelectGestureSurfaces.test.ts also read Kanban.tsx. They check the `testID` and the drag-select ignore marker of the board root, which stays in Kanban.tsx under every option below.
- **Problem:** The file passes the 300-line limit of the repository, because one file holds the public type, the board model, and the render.
- **Impact if no action:** The file grows with each change to the board, and a reader must read past the long type to reach the component. The harm is reading time only.
- **Root question:** How should src/kanban/Kanban.tsx get under 300 lines along its responsibilities?
- **Options:**
  - **A.** Move `KanbanProps<Card>` with its doc comments into a new src/kanban/kanbanTypes.ts, as other folders do with modules such as src/sortable-list/sortableListTypes.ts and src/timeline/timelineTypes.ts. Export the new module from src/kanban/index.ts, so that `KanbanProps` stays public at `@firna/ui/kanban`. Make the declaration-order test read the new file, with the same assertions. Kanban.tsx then has about 235 lines. Effort: Small.
  - **B.** Move the board model into a new pure module, for example src/kanban/kanbanBoardModel.ts: the grouping of cards into columns, the drag layout, and the lookup of the dragged card and its preview slot. Give the module unit tests that call it, and make the grouping test check the new module. Kanban.tsx then has about 280 lines. Effort: Small.
  - **C.** Apply A and B. Kanban.tsx then has about 200 lines. Effort: Small.
- **Left out:**
  - Change nothing: the file stays over the limit, which fails the goal.
  - Remove blank lines or compact the code: the three responsibilities stay in one file, which fails the goal.
- **Wider fix:** None in this item. A file-length lint for TypeScript would prevent the class. But on 2026-11-02, 77 TypeScript files under src passed 300 lines, and a new lint needs a decision of the user.
- **Previous examples:** In the same folder, src/kanban/KanbanColumn.tsx has 391 lines, and src/kanban/useKanbanCardDrag.web.ts has 459 lines.
- **Recommendation:** A. It reaches the limit with one move along the line between the public type and the component, as other folders already do, and it changes no behavior.
- **Action:** fix after merge, apply A, because the file passed the limit before the drag-select branch, and the split belongs outside that branch.
