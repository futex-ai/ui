# `setNativeProps` drops React Native style values on web

- **Severity:** Medium. **Likelihood:** Rare. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-28, from the branch `calummoore/firna-rnw-seam-contract-mhsd`. Its seventh follow-up check found the defect in the evidence of `plans/follow-ups/rnw-host-refs-lack-published-methods.md`, and no item recorded it.
- **Location:** `src/primitives/refs/hostMethods.web.ts:14-15`, `src/primitives/refs/hostMethods.web.ts:72-74`, `src/primitives/dom/resolveStyle.ts`, `src/primitives/dom/styleTables.ts`, `src/primitives/dom/styleValues.ts`, `src/primitives/dom/shadowColor.ts`, `src/primitives/dom/useLayout.ts:195`, `src/primitives/dom/textInputHost.ts:44`, `src/primitives/README.md:93-96`, `tests/unit/domResolveStyle.test.ts:11`, `tests/browser/rnw-fields.spec.ts:108-118`, and `tests/browser/rnw/fieldsFixture.jsx:44`.
- **Reason:** The defect came with pull request #168 on `main`, and the branch that found it moved that code into `src/primitives/refs/` and reused it on the RNW route unchanged.

- **Terms:**
  - **Seam:** a module pair in `src/primitives`, a native file and a `.web` file, through which the components of Firna reach the platform packages.
  - **DOM backend:** Firna's own web renderer under `src/primitives/dom`, which every web app uses when it does not take the RNW route.
  - **RNW route:** an app that draws its own screens with `react-native-web` (RNW) applies `resolveFirnaRnwFile` of `@firna/ui/rnw`, and Firna then draws with RNW too.
  - **Public ref:** a ref prop of a public component, such as `Button.buttonRef`, that receives the host element that the component mounts.
  - **Style translation:** the code that turns a React Native style into the inline CSS of an element: `src/primitives/dom/resolveStyle.ts`, with `styleTables.ts`, `styleValues.ts`, and `shadowColor.ts` beside it.
- **Background:**
  - `setNativeProps` applies props to a host without a render. Firna publishes React Native's own type for it: `NativeMethods` declares `setNativeProps(nativeProps: object)` at `src/primitives/types/hostInstance.ts:55-56`. On iOS and Android, React Native applies its `style` as a React Native style. A number is a length in density-independent pixels, and `paddingHorizontal` sets the left and the right padding.
  - No protocol page names `setNativeProps`. So the published React Native type is the only statement of its meaning, and a fix that keeps that meaning adds no requirement.
  - Both web renderers take the method from `src/primitives/refs/hostMethods.web.ts`:
    - The DOM backend attaches `createSetNativeProps` to its hosts at `src/primitives/dom/useLayout.ts:195`, and `createFieldSetNativeProps` to a text field at `src/primitives/dom/textInputHost.ts:44`.
    - RNW 0.21.4, the installed version, gives a host node no `setNativeProps`. It adds only `measure`, `measureLayout`, and `measureInWindow`, at `node_modules/react-native-web/dist/modules/usePlatformMethods/index.js:23-25`. On the RNW route, `fillMissingHostMethods`, at `src/primitives/refs/hostMethods.web.ts:78-93`, adds the same functions at each public ref that calls `useForwardedHostRef`, such as `Button.buttonRef` and `Input.inputRef`. `src/primitives/README.md:180-196` describes the hook.
  - `createSetNativeProps` runs `Object.assign(node.style, value)` for a `style` prop, at `src/primitives/refs/hostMethods.web.ts:14-15`. `createFieldSetNativeProps` does the same at `:72-74`. So each React Native key and value goes to the style of the element unchanged.
  - The code came with commit `cfd68e3`, pull request #168 of 2026-09-17, when the DOM backend replaced RNW. On `origin/main` at `b17c365`, it is at `src/primitives/dom/useLayout.ts:169` and `src/primitives/dom/textInputHost.ts:91`. Commit `f36d877` of the react-native-web route branch moved it unchanged into `src/primitives/refs/hostMethods.web.ts`. The same commit gave the hosts of RNW these functions, so the defect reached the RNW route with that commit. Before that commit, the call threw there, because the method was missing.
  - A probe in Chromium on 2026-11-28 ran at `f36d877` and at `69e9989`, with the same results:
    - It bundled a fixture twice with the esbuild setup of `tests/browser/rnw/harness.ts:15-36`: with the plugin of `scripts/rnw-esbuild.ts` for the RNW route, and without it for the DOM backend. The page was in standards mode.
    - It called `setNativeProps({ style: { width: 100, paddingHorizontal: 8, opacity: 0.5 } })` on a `Button.buttonRef`.
    - On both renderers, only `opacity: 0.5` applied. The inline `width` stayed empty, because a CSS length needs a unit in standards mode.
    - The inline left and right padding did not change: `16px` with the DOM backend, and empty on the RNW route, where a class of RNW sets the padding. Chromium drops `paddingHorizontal`, because that key is not a CSS property.
  - The style translation gives the correct CSS for such values. `resolveStyle({ width: 12, height: 0 })` gives `12px` and `0px`, at `tests/unit/domResolveStyle.test.ts:56-69`. `paddingHorizontal: 8` gives a `paddingLeft` and a `paddingRight` of `8px`, at `:71-95`. `src/primitives/README.md:93-96` describes the translation.
  - The translation is four modules in `dom/`:
    - `resolveStyle.ts` imports `styleTables.ts` and `styleValues.ts`, at `src/primitives/dom/resolveStyle.ts:16-33`. `styleValues.ts` imports `shadowColor.ts`, at `src/primitives/dom/styleValues.ts:9`.
    - The only other imports are the type `CSSProperties` of `react`, at `src/primitives/dom/resolveStyle.ts:13`, and `SYSTEM_FONT_STACK` from `src/primitives/webStylesheet.ts`, at `:15`. Both renderers load that module.
    - The four modules have 279, 232, 106, and 99 lines, 716 in total.
  - These files import the translation: `View.tsx:25`, `Text.tsx:23`, `TextInput.tsx:51`, `StyleSheet.ts:11`, `imageFit.ts:13`, and `animated/AnimatedStyle.ts:10` in `src/primitives/dom`, and `tests/unit/domResolveStyle.test.ts:11`. The comments at `src/primitives/dom/animated/interpolation.ts:12` and `:29` name `dom/shadowColor.ts`.
  - The RNW route loads no module under `dom/`. The rule is at `src/primitives/README.md:60-62`. The test "RNW bundles of every public subpath exclude the DOM backend and native SVG and icon packages", at `tests/unit/rnw.dist.ts:91-137`, fails on a bundle input under `primitives/dom/`. So `src/primitives/refs/hostMethods.web.ts` cannot import the translation from `dom/`.
  - The branch moved shared code out of `dom/` three times before:
    - Commit `c8ced33` of 2026-11-27 moved `dom/css.ts` to `src/primitives/webStylesheet.ts`.
    - Commit `42e7331` of 2026-11-27 moved the press hooks to `src/primitives/webPress/`, so that the link host can run them on the RNW route.
    - Commit `f36d877` of 2026-11-28 moved these ref methods to `src/primitives/refs/`.
  - The `StyleSheet` export of RNW is also a function. `StyleSheet(styles)` returns a class name and an inline style that RNW translated, at `node_modules/react-native-web/dist/exports/StyleSheet/index.js:161-171`. The `StyleSheet` of React Native is not a function, so the types of the seam do not declare that call.
  - The library calls `setNativeProps` on web nowhere. `grep -rnE "\.(setNativeProps|setSelection)\(" src`, outside `src/primitives/dom/`, `src/primitives/types/`, and `src/primitives/refs/`, finds three lines. One is the native rich-text call at `src/rich-text/nativeRichTextFocus.ts:65`. The other two call the own `setSelection` function of the data grid. So only app code meets the defect, through a public ref.
  - A `null` value clears a property today, because the style of an element takes `null` as an empty value. `resolveStyle` drops a `null` from its result, at `tests/unit/domResolveStyle.test.ts:48-49`, so a translated style alone does not clear.
  - `tests/browser/rnw-fields.spec.ts:108-118` calls `setNativeProps` on five public refs, on both renderers, through `dim` at `tests/browser/rnw/fieldsFixture.jsx:44`. `dim` passes only `{ style: { opacity: 0.5 } }`, a value that needs no translation. So no test covers a length or a React Native key.
- **Problem:** On both web renderers, `setNativeProps` copies a React Native `style` onto the style of the element unchanged. So a number for a length and a React Native key such as `paddingHorizontal` do not apply. In the probe, only `opacity: 0.5` of `{ width: 100, paddingHorizontal: 8, opacity: 0.5 }` applied.
- **Impact if no action:** On web, a call of `setNativeProps` with a length or a React Native style key changes nothing and reports no error, although the same call works on iOS and Android.
- **Root question:** How does `setNativeProps` apply a React Native style on every web renderer?
- **Options:**
  - **A.** Keep the translation in `dom/`, and let the RNW route load its four modules. Change the rule at `src/primitives/README.md:60-62` and the bundle test at `tests/unit/rnw.dist.ts:91-137`, so that they allow these modules. Then both functions of `hostMethods.web.ts` translate the style. A weakens a test of the RNW route, which only the user can approve, so A is blocked. Effort: Small.
  - **B.** Move the translation out of `dom/` into a shared web folder, for example `src/primitives/webStyle/`, as the press hooks moved to `src/primitives/webPress/`:
    - Move `resolveStyle.ts`, `styleTables.ts`, `styleValues.ts`, and `shadowColor.ts`. Change the imports and the two comments that **Background** lists.
    - In both functions of `src/primitives/refs/hostMethods.web.ts`, assign `resolveStyle(value)` in place of the raw value. `resolveStyle` returns CSS properties in camel case, with units, which `Object.assign(node.style, …)` applies.
    - Keep the clear of a `null` value: for each key that the caller sets to `null`, clear each CSS property that the translation gives for that key. For example, `paddingHorizontal: null` clears the left and the right padding.
    - Move the bullet at `src/primitives/README.md:93-96` to a section for the new folder, next to the sections `webPress/` and `refs/`.
    - Update the evidence paths of `plans/follow-ups/transport-scrubber-shrinks-to-knob.md` and `plans/follow-ups/segmented-equal-wrap-no-effect.md`, which cite `src/primitives/dom/resolveStyle.ts:183-190`.
    - Add cases to `tests/browser/rnw-fields.spec.ts`, with their calls in `tests/browser/rnw/fieldsFixture.jsx`. Each case calls `setNativeProps({ style: { width: 100, paddingHorizontal: 8 } })` on `Button.buttonRef` or on `Input.inputRef`. It expects a computed width of `100px` and a left and right padding of `8px`, on both renderers. A second call with `paddingHorizontal: null` clears the padding again.
    - Run `node --import tsx --test tests/unit/domResolveStyle.test.ts`, `npm run typecheck`, and `npm run typecheck:web`. Then run `npm run build`, `npm run test:dist`, and `npx playwright test tests/browser/rnw-fields.spec.ts`. The complete gate is `cargo xtask check`.
    - Cost: the RNW route then also loads the 716 lines of the translation, with each component that calls `useForwardedHostRef`, such as `Button`.
    - Effort: Medium.
  - **C.** Give `createSetNativeProps` and `createFieldSetNativeProps` a style translator as a parameter. The DOM backend passes `resolveStyle`. `fillMissingHostMethods` passes the inline style of the `StyleSheet` function of RNW, which it imports through the seam `reactNative`. Costs:
    - React Native has no such call, so the types of the seam do not declare it, and C needs a cast.
    - With the DOM backend, `hostMethods.web.ts` then imports the seam, which loads `dom/`, and `dom/useLayout.ts` imports `hostMethods.web.ts`. That is an import cycle.
    - The RNW route needs no extra code, and its CSS is the output of RNW itself.
    - Effort: Medium.
- **Left out:**
  - A small table of its own in `hostMethods.web.ts`, for example `px` for a number and the expansion of `paddingHorizontal`: it covers only the keys in its table, so a React Native value outside it still drops, such as a `transform` array or `shadowOpacity`. It fails the goal.
  - Document that a `style` in `setNativeProps` takes CSS values on web: the published type keeps the meaning of React Native, and the same call then needs other values on native, so it fails the goal.
  - Remove `setNativeProps` from the published web types: it answers another root question, which `plans/follow-ups/rnw-host-refs-lack-published-methods.md` holds as its option D. It also deletes functionality on `origin/main`.
  - Change nothing: a React Native style keeps dropping on web, so it fails the goal.
- **Wider fix:** B. One shared translation then serves every web path that applies a React Native style, so a later web module has no reason to copy a raw style.
- **Previous examples:** None found. Other web code that writes the style of an element, such as `src/announcer.ts:47` and `src/modal/webModalScrollLock.ts:39-47`, writes CSS values, not React Native styles.
