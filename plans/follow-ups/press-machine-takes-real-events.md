# Press machine accepts hand-built stand-in events

- **Severity:** Medium. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-02, from the branch `calummoore/dragselectableprovider-improvements`, finding 16.
- **Location:** src/primitives/webPress/pressMachine.ts:29, src/primitives/webPress/pressMachine.ts:86, src/primitives/webPress/pressMachine.ts:178, src/primitives/webPress/pressMachine.ts:201, src/primitives/webPress/pressMachine.ts:259, src/primitives/webPress/usePress.ts, tests/unit/domPress.test.ts:87, tests/unit/domPressFakes.ts:66
- **Reason:** The change reaches the press machine and each of its call sites, which the drag-select branch did not otherwise change, and it serves press paths that the branch did not touch. That branch merged on 2026-11-06, as commit `747b2b5`.

- **Terms:**
  - **Press machine:** the state machine behind the `Pressable` of the library's own DOM backend and behind the web link host, in src/primitives/webPress/pressMachine.ts. It ports the press responder of `react-native-web`.
  - **`PressEvent`:** the event type that the press machine functions take, at src/primitives/webPress/pressMachine.ts:29. Its `nativeEvent` is any record, and its `target` and `currentTarget` can be `null`.
  - **`fromDomEvent`:** the function at src/primitives/webPress/pressMachine.ts:99 that wraps a real DOM event as a `PressEvent`.
  - **Stand-in event:** a `PressEvent` that code builds by hand, with no DOM or React event behind it.
  - **DOM backend:** Firna's own web renderer under src/primitives/dom, which every web app uses when it does not take the route of `react-native-web`.
- **Background:**
  - The DOM backend's `Pressable` in src/primitives/dom/Pressable.tsx feeds the press machine through `usePress` in src/primitives/webPress/usePress.ts. The web link host in src/primitives/link.web.tsx also uses `usePress`, but it passes only its own state setter, so no app callback gets its events.
  - An app that draws its own screens with `react-native-web` can apply the rule of `@firna/ui/rnw`, so that the library draws with `react-native-web` too. A library `Pressable` is then the `Pressable` of `react-native-web`, which does not use the press machine.
  - The machine calls `onPressIn`, `onPressMove`, `onPressOut`, `onPress`, and `onLongPress` with the event that it gets. `onPressMove` gets each `pointermove` through `fromDomEvent`, at src/primitives/webPress/usePress.ts:118-119. `press()` casts that event to `GestureResponderEvent` at src/primitives/webPress/pressMachine.ts:179.
  - The normal paths pass the React event of the host element, or the DOM event of a document listener through `fromDomEvent`.
  - The exported functions `start`, `receiveSignal`, `press`, and `isValidKeyPress` take `PressEvent`, so any object with its keys compiles.
- **Problem:** Nothing stops a caller from passing a stand-in event, and the callbacks then get no pointer data. This happened when a drag-select drag started on a pressed `Pressable`: `endPointerPresses` in src/primitives/webPress/usePress.ts ended the press with a stand-in event with `nativeEvent: {}` and `null` targets, and in Chromium `onPressOut` got `undefined` coordinates where a normal release gives numbers. That path is fixed: `endPointerPresses` now takes the pointer event that started the drag, and `onPressOut` gets that event.
- **Impact if no action:** A later path that ends a press without a pointer event, such as another gesture that takes over the pointer, can build a stand-in event again. A callback that reads the coordinates or the targets of that event can then throw or compute wrong values.
- **Root question:** How does the press machine make sure that every press callback gets an event that a real DOM or React event backs?
- **Options:**
  - **A.** Keep the `PressEvent` type, and add a unit test for each path that ends a press. Each test checks that the callback event has numeric coordinates and real targets. Cost: it guards only the paths that have a test, and each new path needs its own test. Effort: Small.
  - **B.** Make the exported functions `start`, `receiveSignal`, `press`, and `isValidKeyPress` take a real DOM `Event` or a React `SyntheticEvent`, and convert the event inside the machine, so a stand-in event does not compile. Change each call site in src/primitives/webPress/usePress.ts. The type `PressHandlers`, at src/primitives/webPress/pressMachine.ts:41-46, also takes a `PressEvent`. The DOM `Pressable` passes those handlers to its host at src/primitives/dom/Pressable.tsx:157-165, and the link host types and passes them at src/primitives/link.web.tsx:76-77 and :164-166. Make the tests build real events in place of the hand-built ones: the `downEvent` at tests/unit/domPress.test.ts:87, and the `pointerDown` helper in tests/unit/domPressFakes.ts. The unit tests run in Node, which has `Event` but no `PointerEvent`, `MouseEvent`, or `KeyboardEvent`. So the tests need a DOM engine such as jsdom, or test doubles of those event types. Cost: it changes the press machine, each of its call sites, and the event fixtures of the tests. Effort: Medium.
- **Left out:**
  - Fill in the missing fields of a stand-in event: it repeats the event conversion and gives callbacks invented data, so B is better on every point.
  - Skip `onPressOut` when a press ends without a pointer event: `onPressIn` then has no matching `onPressOut`, which fails the goal.
  - No event, or an optional event, for `onPressOut`: the callback type is then narrower than the type of React Native. src/primitives/README.md:216-217 forbids a narrower type, and tests/unit/primitiveTypesCompat.test.ts enforces that rule.
  - A branded `PressEvent` that only the converters can create: it needs the same call-site changes as B and keeps the conversion at each call site, so B is better on every point.
  - Change nothing: the fixed path stays fixed, but nothing stops the next path, which fails the goal.
- **Wider fix:** B. It removes the class: a stand-in event does not compile without a cast.
- **Previous examples:** The drag-select path under **Problem**. In the tests, tests/unit/domPress.test.ts:87 builds a `downEvent` with `nativeEvent: {}` for the press delay tests, and the `pointerDown` helper in tests/unit/domPressFakes.ts builds a `pointerdown` by hand.
